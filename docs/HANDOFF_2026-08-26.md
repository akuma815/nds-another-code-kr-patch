## 이번 세션 목표와 결론

대사 편집기의 항목별 한글 글자 상한을 ARM9 렌더러 구조와 실제 번역 CSV 전체를 기준으로 다시 계산하고, 미리보기와 정적 검사를 그 결과에 맞췄다.

기존의 `대화 17×2 / 시스템 17×2 / 중앙 17×3 / auxiliary 16×1` 잠정 규칙은 폐기했다. 현재 자동 규칙은 다음과 같다.

| 소비 유형 | 식별 | 한글 상한 | 판정 |
|---|---|---:|---|
| 2줄 대화창 | `%w(1xx)`, `%w(3xx)`, `%w(5xx)` | 17자 × 2줄 | 정적 렌더러 구조 확인 |
| 1줄 메시지창 | `%w(2xx)`, `%w(4xx)` | 17자 × 1줄 | 정적 렌더러 구조 확인 |
| 항목/정보창 | 명시적 `%w`가 없는 strong script | 17자 × 2줄 | 공통 렌더러 + 원문 경계 확인 |
| 창 없는 회상 자막 | `%w(00n)` | `19-n`자 × 2줄 | 화면 우측 물리 경계 계산 |
| 전체 화면 문서/인트로 | overlay 000 자유 배치 | 19자 × 최대 8줄 | 물리 폭 + 원문 템플릿 확인 |
| auxiliary/isolated | 후보 테이블 | 강제 검사 보류 | 소비 함수 미추적 |

`auxiliary` 689행과 `isolated_candidate` 41행은 하나의 창을 공유한다는 증거가 없으므로 임의의 공통 상한을 만들지 않았다. 에디터에서는 노란색 `검사 보류`로 표시하며, 실제 소비 화면을 추적한 뒤 `text_id`별 override를 저장해야 한다.

## 계산 근거

- 승인된 한글 폰트 전진폭: 12px, 셀: 16×16px.
- ARM9 `0x0202D43C..0x0202D4DC`: 글리프 시작 X와 글자당 12px 증가.
- ARM9 `0x0202CB9C..0x0202CBBC`: `%r`에서 X를 0으로 되돌리고 Y를 16px 증가.
- ARM9 `0x0202A6E4..0x0202A818`: 창 폭 30타일.
  - 타입 1/3/5: 30×6타일, 안쪽 208×32px.
  - 타입 2/4: 30×3타일, 안쪽 208×16px.
- 가로 상한: `floor((208-16)/12)+1 = 17`.
- 창 없는 `%w(00n)` 상한: 시작 X가 `24+12n`이므로 `floor((256-(24+12n)-16)/12)+1 = 19-n`.

원문 전체 실측도 계산과 일치했다.

## 추가 확인 — `%z(01)`

- `%z` 디스패치: ARM9 `0x0202CCF8`, 핸들러 `0x0202A994`.
- `%z` 인수의 일의 자리는 글자 출력 속도 모드다. 일의 자리가 0이면 현재 속도를 유지한다.
- `%z(01)`은 속도 모드 1로 바꾸며, 각 글리프 출력 뒤 대기 카운터를 4 업데이트 틱으로 설정한다.
- 비교: 모드 2는 7틱, 모드 3은 12틱, 모드 4/5는 0틱이다.
- 따라서 `%z(01)`은 빠른 순차 출력이며 화면에 보이는 문자가 아니다. 번역할 때 지우거나 옮기지 않고 그대로 보존한다.
- `%z(40)`처럼 두 자리인 값은 `속도 4`가 아니다. 일의 자리 0이므로 속도는 유지하고 상위 자리 상태만 변경한다.

## 추가 확인 — `%f(2)`

- `%f` 디스패치: ARM9 `0x0202CB4C..0x0202CB88`.
- 인수를 파싱한 뒤 `0x020089F4`가 값을 4배 해 현재 글자 팔레트 오프셋으로 저장한다.
- 원본 글리프의 2bpp 비투명 값 1~3에는 `0x02008714..0x02008724`에서 이 오프셋이 더해진다.
- 따라서 `%f(2)`는 팔레트 오프셋 8, 즉 최종 인덱스 9~11의 보조 글자 팔레트 그룹을 선택한다.
- 용례는 디의 대사 전체와 조사 메시지 안의 대상 명칭 강조가 대표적이다.

## 추가 확인 — `%w(200)`과 `%w(400)`의 차이

- ARM9 로드 베이스는 NDS 헤더 기준 `0x02004000`이며, `%w` 디스패치는 `0x0202D118..0x0202D13C`, 인수 분해와 창 생성은 `0x0202A500..0x0202A830`이다.
- `200`과 `400`은 모두 화면 아래쪽의 30×3타일 1줄 창이다. 글리프 기준선도 둘 다 Y=`0xA0` 경로(`0x0202D428..0x0202D47C`)를 사용하므로 한글 상한은 동일하게 17자×1줄이다.
- 차이는 백의 자리 창 타입이다. 타입 2(`200`)는 표시 리소스 슬롯 `+0x2C`, 타입 4(`400`)는 슬롯 `+0x28`을 선택한다. 위치와 크기는 같지만 창의 표시 스타일/연출용 그래픽 리소스가 다르다.
- 원문 용례상 `200`은 조사 결과·획득/사용 알림 같은 일반 시스템 메시지가 중심이고, `400`은 장면 연출 중 짧은 독백·서술·감탄에 주로 쓰인다.
- 번역 줄을 `%h`로 둘로 나눌 때는 원문의 타입을 바꾸지 않고 각 페이지에 같은 `%w`를 반복한다. 예: `%w(200)첫 줄%h%w(200)둘째 줄%h%e`.
- 실제 RGB 색은 화면이 적재한 16색 팔레트에 따라 결정되므로 `%f(2)=항상 특정 RGB`로 고정해서 해석하면 안 된다.
- 대응 그룹: `%f(0)` 인덱스 1~3, `%f(1)` 5~7, `%f(2)` 9~11, `%f(3)` 13~15. 번역에서는 전환 위치를 보존한다.
